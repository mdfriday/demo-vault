At the start of the function an empty Definition is defined. It seems the data will all be stored in here.

```golang
// Definition is the LLB definition structure with per-vertex metadata entries
// Corresponds to the Definition structure defined in solver/pb.Definition.
type Definition struct {
   Def      [][]byte
   Metadata map[digest.Digest]pb.OpMetadata
   Source   *pb.Source
}
```
The Definition struct does not look complicated either. Only three items. The last two are custom types, and they start with pb. What is this pb?
It turns out this is the pb under `solver`. From `ops.proto` you can see this is Google's [Protocol Buffers](https://developers.google.com/protocol-buffers/docs/proto3). After looking at the docs, the rough meaning is that it is used to transmit data. Its trait is that the compression algorithm is very efficient. A language built specially for the data-transmission scene.
Then what we can foresee here is that our Definition may more or less need to be transmitted across the network to the remote for processing.

Then look at the next sentence:

Here comes a lowercase marshal again. From the arguments, the second is s.Output().Vertex(...). Based on the current understanding, this is the ExecState we saw last time, that is, the second part.
def is also passed in. It seems the guess was right. It really is used to store data.

Then look at the small marshal:
```golang
func marshal(ctx context.Context, v Vertex, def *Definition, s *sourceMapCollector, cache map[digest.Digest]struct{}, vertexCache map[Vertex]struct{}, c *Constraints) (*Definition, error) {
   if _, ok := vertexCache[v]; ok {
      return def, nil
   }
   for _, inp := range v.Inputs() {
      var err error
      def, err = marshal(ctx, inp.Vertex(ctx, c), def, s, cache, vertexCache, c)
      if err != nil {
         return def, err
      }
   }

   dgst, dt, opMeta, sls, err := v.Marshal(ctx, c)
   if err != nil {
      return def, err
   }
   vertexCache[v] = struct{}{}
   if opMeta != nil {
      def.Metadata[dgst] = mergeMetadata(def.Metadata[dgst], *opMeta)
   }
   if _, ok := cache[dgst]; ok {
      return def, nil
   }
   s.Add(dgst, sls)
   def.Def = append(def.Def, dt)
   cache[dgst] = struct{}{}
   return def, nil
}
```
You can see there is a recursive call to the small marshal. If v.Inputs() is not empty, the recursion is triggered:

![buildkit-dag-copy.jpg](./img/buildkit-dag-copy.jpg)

Jia Dazhi also said: when you look at recursion, mainly look at two points. One is to abstract what the recursive function has to do, that is, the action that will be called repeatedly. The other is to look at the exit, that is, the place where the recursion exits.

This is a good place to try that method:
- The recursive function is the small marshal. It is mainly used to organize Vertex into the matching Definition.
- The exit is v.Inputs(). That is, it always finds the node with no Inputs and starts processing. Here that is SourceOp. It is the first Vertex. There is no input anymore.
It keeps looking upward, finds the last node with no dependency, and starts processing. It seems to be the legendary depth-first algorithm.

How is the conversion done, concretely?
We get the next sentence:
```golang
dgst, dt, opMeta, sls, err := v.Marshal(ctx, c)
```
The v here is our Vertex. We now have SourceOp and ExecOp. Let's see how their big Marshal is implemented.
## SourceOp Marshal()
```golang
func (s *SourceOp) Marshal(ctx context.Context, constraints *Constraints) (digest.Digest, []byte, *pb.OpMetadata, []*SourceLocation, error) {
   if s.Cached(constraints) {
      return s.Load()
   }
   if err := s.Validate(ctx, constraints); err != nil {
      return "", nil, nil, nil, err
   }

   if strings.HasPrefix(s.id, "local://") {
      if _, hasSession := s.attrs[pb.AttrLocalSessionID]; !hasSession {
         uid := s.constraints.LocalUniqueID
         if uid == "" {
            uid = constraints.LocalUniqueID
         }
         s.attrs[pb.AttrLocalUniqueID] = uid
         addCap(&s.constraints, pb.CapSourceLocalUnique)
      }
   }
   proto, md := MarshalConstraints(constraints, &s.constraints)

   proto.Op = &pb.Op_Source{
      Source: &pb.SourceOp{Identifier: s.id, Attrs: s.attrs},
   }

   if !platformSpecificSource(s.id) {
      proto.Platform = nil
   }

   dt, err := proto.Marshal()
   if err != nil {
      return "", nil, nil, nil, err
   }

   s.Store(dt, md, s.constraints.SourceLocations, constraints)
   return s.Load()
}
```
You can see `proto, md := MarshalConstraints(constraints, &s.constraints)` produced proto:
```golang
return &pb.Op{
   Platform: &pb.Platform{
      OS:           c.Platform.OS,
      Architecture: c.Platform.Architecture,
      Variant:      c.Platform.Variant,
      OSVersion:    c.Platform.OSVersion,
      OSFeatures:   c.Platform.OSFeatures,
   },
   Constraints: &pb.WorkerConstraints{
      Filter: c.WorkerConstraints,
   },
}, &c.Metadata
```
That is, here SourceOp is converted into pb.Op:
```golang
proto.Op = &pb.Op_Source{

}
```

Overall, the data-conversion flow really has become a little clearer.
Use depth-first recursion to organize every Vertex. Here we have to thank llb.State for organizing the relationships between Vertices for us.
Then every Op, that is SourceOp and ExecOp, and both provide a Marshal method, the place that really does the data conversion. Plus the help of Proto Buffer, the concrete serialization does not need us to worry about it.
That way we finish the conversion from llb.State to Definition. Among them, every temporary Op, SourceOp and ExecOp, is converted into a standard pb.Op.

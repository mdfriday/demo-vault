Looking back at this stretch of code, Yuan Xiaobai felt it was clear at a glance, mind clear and spirit fresh. The feeling was like the two channels, Ren and Du, had been opened.

* Through the method dockerfile2llb.Dockerfile2LLB, convert dockerfile into State
* Then convert the returned State, st.Marshal, into def, Definition
* Then parse once more with c.Solve. The c here, client, is the llbBridge that was passed in. And pass in def.ToPB()
* Finally get the parse result, and return

The data structures are not much of a problem anymore. They help us understand these nearly 500 lines of code, and it becomes easy.
But why, this morning, call llbBridge to parse once more?
The earlier understanding was: the arguments passed in here are different from the arguments passed in the first parse, so the result is different. Look at the parse source again:
```golang
func (b *llbBridge) Solve(ctx context.Context, req frontend.SolveRequest, sid string) (res *frontend.Result, err error) {
   if req.Definition != nil && req.Definition.Def != nil && req.Frontend != "" {
      return nil, errors.New("cannot solve with both Definition and Frontend specified")
   }

   if req.Definition != nil && req.Definition.Def != nil {
      res = &frontend.Result{Ref: newResultProxy(b, req)}
      if req.Evaluate {
         _, err := res.Ref.Result(ctx)
         return res, err
      }
   } else if req.Frontend != "" {
      f, ok := b.frontends[req.Frontend]
      if !ok {
         return nil, errors.Errorf("invalid frontend: %s", req.Frontend)
      }
      res, err = f.Solve(ctx, b, req.FrontendOpt, req.FrontendInputs, sid, b.sm)
      if err != nil {
         return nil, err
      }
   } else {
      return &frontend.Result{}, nil
   }

   return
}
```
Sure enough. The same parse has two branches here. One is when req.Definition is not empty. One is when req.Frontend is not empty. The earlier time was because the req.Frontend passed in was dockerfile.v0, read from the `buildctl build` command-line arguments.
And this time it is a call actively started by the Frontend dockerfile.Build method. The req.Definition passed in is not empty.

Then it matches. The result res that is finally returned is `res = &frontend.Result{Ref: newResultProxy(b, req)}`.
That is to say, after going around in a circle, the result finally returned is the Result in bridge.go.

Inside SourceOp's CacheMap, `s.instance` needs to be obtained, and here it depends on `s.sm.Resolve`. You can see sm is actually source.Manager, and it depends on the Resolve method.
Yes, another Resolve. Yuan Xiaobai said to himself: naming really is critical. If everyone has resolve, understanding it is too easy to mix up.
Then look at this Resolve:
```golang
func (sm *Manager) Resolve(ctx context.Context, id Identifier, sessM *session.Manager, vtx solver.Vertex) (SourceInstance, error) {
   sm.mu.Lock()
   src, ok := sm.sources[id.ID()]
   sm.mu.Unlock()

   if !ok {
      return nil, errors.Errorf("no handler for %s", id.ID())
   }

   return src.Resolve(ctx, id, sessM, vtx)
```

To verify his idea, Yuan Xiaobai decided to check whether this instance has a Resolve method.
The result was as expected. It is right here:
```golang
func (is *Source) Resolve(ctx context.Context, id source.Identifier, sm *session.Manager, vtx solver.Vertex) (source.SourceInstance, error) {
   imageIdentifier, ok := id.(*source.ImageIdentifier)
   if !ok {
      return nil, errors.Errorf("invalid image identifier %v", id)
   }

   platform := platforms.DefaultSpec()
   if imageIdentifier.Platform != nil {
      platform = *imageIdentifier.Platform
   }

   pullerUtil := &pull.Puller{
      ContentStore: is.ContentStore,
      Platform:     platform,
      Src:          imageIdentifier.Reference,
   }
   p := &puller{
      CacheAccessor:  is.CacheAccessor,
      LeaseManager:   is.LeaseManager,
      Puller:         pullerUtil,
      id:             imageIdentifier,
      RegistryHosts:  is.RegistryHosts,
      ImageStore:     is.ImageStore,
      Mode:           imageIdentifier.ResolveMode,
      Ref:            imageIdentifier.Reference.String(),
      SessionManager: sm,
      vtx:            vtx,
   }
   return p, nil
}
```
It actually returns a Puller instance. But turning his head and thinking, that is also right. If I am a SourceOp, what matches is the From instruction of a Dockerfile. If I want to get the information of this parent container, naturally I need an object to help me get it. Then here there is an object used to provide storage service, ContentStore, and a cache strategy used to raise efficiency, CacheAccessor.

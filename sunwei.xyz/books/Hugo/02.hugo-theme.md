# A custom Hugo theme

Hugo can create a site, and it can also create your own theme.
Take the site [sunwe.xyz](https://sunwei.xyz) as the example.
Separate the site's content from the theme, so we can focus on writing.
People with the same need can also reuse the theme.

## What we need

The goal is to pull the site theme out: separate content from layouts and static, and bring those in as a theme.

The steps:

* Create a theme repository
* Split the templates and styles out of the original site
* Import the theme

## How to do it

We carry out the steps above, one by one.

### Create the theme repository

The site is a personal brand. The need is not complicated, so keep it simple.
The theme is named `zero`, meaning a starting point.

First create an empty zero repository on GitHub, then use the Hugo command to generate the default theme directories:
```shell
➜  zero git:(main) ✗ hugo new theme .
Creating theme at /Users/sunwei/github/sunwei/zero/themes
➜  zero git:(main) ✗ ls
LICENSE   README.md public    resources themes
```

Hugo thinks we are inside a site, creating a theme for that site.
What we actually need is the contents of themes.
In this example, that is really just the theme config file `theme.toml`.
After copying it to the repository root, update the description as follows:
```toml
name = "Zero"
license = "MIT"
licenselink = "https://github.com/sunwei/zero/blob/master/LICENSE"
description = "Hugo Theme for sunewi.xyz"
homepage = "https://sunwei.xyz/"
demosite = "https://sunwei.xyz"
tags = ["zero", "sunwei.xyz"]
features = ["clean"]
min_version = "0.41.0"

[author]
  name = "Sun Wei"
  homepage = "https://sunwei.xyz"

```

The other files can be removed. We are not creating a theme from nothing. We are pulling the sunwei.xyz site theme out on its own.

So the theme can be imported as a module, we also need a Go module file `go.mod` in the repository root, with this content:
```go
module github.com/sunwei/zero

go 1.18
```
Hugo modules are built on Go modules.
The first line above is the Go module name, `github.com/sunwei/zero`. Importing this module means importing that path.
The second line is the supported Go version.

With the theme config and the Go module info ready, we can bring the site theme in.

### Split the templates and styles out of the original site

Open the [site source](https://github.com/sunwei/xyz).
Copy the layouts and static directories into the root of the zero theme repository.
The zero theme directory now looks like this:
```shell
➜  zero git:(main) tree
.
├── LICENSE
├── README.md
├── go.mod
├── layouts
│   ├── index.html
│   ├── partials
│   │   ├── foot.html
│   │   ├── head.html
│   │   └── language.html
│   └── taxonomy
│       └── taxonomy.html
├── static
│   └── css
│       └── style.css
└── theme.toml

5 directories, 10 files
```

The zero theme is done at this point.
Push the update, and it is a Hugo theme anyone can use.
It really is convenient.

### Import the theme

The theme is created. Next is using it.
Open the [site source](https://github.com/sunwei/xyz) and remove the layouts and static directories.

First import the theme in `config.toml`:
```toml
baseURL = 'https://sunwei.xyz/'
title = 'sunwei.xyz'
theme = "github.com/sunwei/zero"

defaultContentLanguage = 'zh'
[languages]
[languages.zh]
languageName = '中文'
contentDir = 'content'
weight = 1

[languages.en]
languageName = 'English'
contentDir = 'content.en'
weight = 2
```

Then create the Go module file `go.mod`:
```go
module github.com/sunwei/xyz

go 1.18
```

Update the module config with the Hugo module command:
```shell
➜  xyz git:(master) hugo mod get -u
go: no module dependencies to download
hugo: downloading modules …
go: downloading github.com/sunwei/zero v0.0.0-20221005003323-b204559ecb5e
go: added github.com/sunwei/zero v0.0.0-20221005003323-b204559ecb5e
hugo: collected modules in 2784 ms
```

Look at go.mod again. The module info was inserted automatically:
```go
module github.com/sunwei/xyz

go 1.18

require github.com/sunwei/zero v0.0.0-20221005003323-b204559ecb5e // indirect
```
You can also set the version yourself, but only if zero has published a concrete version.
The `Hugo mod` command can also manage updates for us.

Look at the sunwei.xyz site repository now:
```shell
➜  xyz git:(master) tree
.
├── CNAME
├── README.md
├── command.sh
├── config.toml
├── content
│   └── _index.md
├── content.en
│   └── _index.md
├── go.mod
└── go.sum

2 directories, 8 files

```

Compared with before:
```shell
➜  xyz git:(master) tree
.
├── CNAME
├── README.md
├── command.sh
├── config.toml
├── content
│   └── _index.md
├── content.en
│   └── _index.md
├── layouts
│   ├── index.html
│   ├── partials
│   │   ├── foot.html
│   │   ├── head.html
│   │   └── language.html
│   └── taxonomy

    └── css

```

It is cleaner.
We can focus more on writing the content.
Thanks, Hugo.
